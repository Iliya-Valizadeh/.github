# Security policy

## In plain words

Do not post personal financial data in issues. If you find a security problem, do not
describe it in a public issue. Ask for a private way to send the details first.

## Do not post personal financial data in issues

Some of my repos work with bank, credit or fraud data. They use public or synthetic
data sets only. Please keep it that way. Do not post personal financial data in issues,
pull requests, comments or attached files. This covers your own data and anyone
else's. Examples:

- account, card or loan numbers
- a Social Insurance Number or any other government ID number
- bank statements, pay stubs, tax slips or credit reports
- screenshots or files that show any of the above

If you need to show a problem with real data, make a small made-up example with the same
shape instead. If you see personal financial data in an issue, tell me and I will delete
it.

## Reporting a security problem

A security problem is a flaw that could let someone see data they should not see, run
code they should not run, or take over an account or a system.

1. Do not open a public issue with the details.
2. If the repo's "Security" tab has a "Report a vulnerability" button, use it. That
   sends the report to me in private.
3. If there is no such button, open an issue with the title "Security contact request"
   and no other details. I will reply with a private way to send them.

I will reply as soon as I can, tell you whether I can reproduce the problem, and credit
you in the fix if you want credit.

## Supported versions

Only the latest version on the `main` branch gets security fixes.
